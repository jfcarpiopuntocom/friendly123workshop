## Root cause audited
C21a coordinator claims opId that committed to DO remains irreversibly barred from legacy across reload. C16a reconciler currently handles business-committed by store.remove(opId), deleting the sole durable IDB entry; C21a only caches opId in a process-local Set. After Safari/PWA reload, a second coordinator sees zero pending and no committed marker, so canDispatchOnLegacy(same opId) returns true -> potential double charge in legacy. Existing test #4 only reloads BEFORE draining; it misses post-commit reload.

## Minimal safe complete remedy
Extend existing C16b IndexedDB version in-place using v2 additive object-store `settled_ops` under the SAME database. Save a tiny namespace+opId committed tombstone and DELETE pending op in ONE readwrite transaction across both object stores, resolve only on tx.oncomplete. Never persist PIN, token, receipt or amounts in marker. Any transaction failure leaves pending op durable. C16a reconciler calls atomic markCommitted where available, with current fallback for test-only in-memory stores. C21a coordinator hydrates BOTH pending and terminal marker opIds before any legacy dispatch; if the committed-marker store is unreadable/unsupported it returns fail-closed. No expiry/GC of committed opIds, preserving permanent no-double-charge contract. Existing old DB v1 upgrades to v2; version mismatch in older tab fails closed. Source edits only three modules (IDB, reconciler, coordinator) + C21a test + existing IDB test if needed; do not modify pilot, docs or Cloudflare, Gemini C23 reservations.
