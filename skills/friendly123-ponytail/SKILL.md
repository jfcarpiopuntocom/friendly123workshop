## Ponytail loop: RED → minimum fix → GREEN → evidence

- Pick the highest-leverage **root cause** that replaces a legacy path, not a symptom by complaint chronology. Keep direct reports by Belén as high-priority acceptance criteria.
- Select the imported, mature component already present in the assembly; connect its existing API end-to-end. Define the existing writer that is retired, and show that there is only one commercial authority.
- Demonstrate the defect on **actual source** (or explicitly label a synthetic fixture); record RED run and exact SHA. Do not weaken assertions, alter the fixture's objective, increase timeouts to silence failures, or count a failed harness as a business failure.
- Apply one minimal complete code change. Run targeted tests plus integrated CI on the final SHA. Distinguish code unit tests, real browser Chromium/WebKit, real Workerd SQLite, synthetic remote canary, and the user's physical Opera PC / Safari iPhone.
- Preserve a failback with durable `opId`, source facts and proof. Write a report to `reports/` and Notion: diff, red/green, negative tests, CI URL, version, exact master/estable/previo state, remaining blockers and next graft.
- Release only against the approved candidate and all relevant gates. CI green alone does not certify physical business convergence. Never label a draft PR or queued workflow as deployed.
